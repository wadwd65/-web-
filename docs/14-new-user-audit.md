# v0.19 · 新用户流程审核与下一步建议

2026-10-29。先完成闪烁/性能与音乐修改，再以新会话、无业务材料的状态逐一走八事务。本报告是内部新用户视角走查，不是多人用户研究。仅桌面1280×720，使用合成材料，没有输入真实合同或个人资料。

## 结论

八件事均能完成当前限定范围内的“进入→材料→处理→结果/路线→导出或提问→切换”。结果解释、原文回看与共享清单有实际价值。主要不便已经从“入口不能用”转为“入口含义不一致、填表负担较重、保存边界不明显”。下一轮优先解决这些问题，保留现在的银蓝动态空间；无需为本轮性能任务重做视觉世界。

## 实际走过的路径

| 环节/模块 | 实际行为与结果 | 新用户感受 |
| --- | --- | --- |
| 首次进入 | 出现可跳过的入场；音乐默认不播；首页有准备材料/带走什么 | 入口气氛明确；英文、编号与多个平行入口会分散第一次找任务的注意力 |
| 事务目录 | 点Offer行，返回总览预览；还需点“进入Offer对比” | 与底部一击进入不同，容易以为没点成功 |
| Offer | 两份合成条件→对齐→117000/120000→收集2问题 | 对比结果明确；初次同时展开约16个字段，必填、可选和不明项缺少明显层级 |
| 合同 | 合成277字→核对7项/3待确认；原文/依据/问题入口可见 | 闭环清楚；多数现实材料是照片/PDF，当前只是预览，仍需自己准备文字 |
| 工资 | “载入示例金额”直接生成实发6534.00 | 金额清楚；示例行为与Offer/个税仅填入再处理不同；结果首屏应持续标明示例来源 |
| 个税 | 合成范围/金额→公式税额1080、预缴差额920 | 公式与实际申报区分清楚；新人仍可能不知道个人缴费、附加扣除和预缴额去哪里查 |
| 社保医保 | 广州参保/上海就医→4步路线→勾1步/记备注 | 分支选择易懂；多处“官方办理/查询入口”只到平台首页，跳转后还需自己找业务 |
| 租房 | 合成文字/金额→7类定位、首次7200→回看原文 | 引用与核实问题有帮助；租房与合同材料输入方式不同，需要明确解释 |
| 补贴 | 只选广州、其余未知→保留4项待确认 | 未知处理诚实；“补贴匹配”名称比一条广州政策的实际覆盖面大，范围应在点击前可见 |
| 离职 | 合成协商解除/2026-11-30→5步台账→实际TXT下载 | 能带走记录；重新生成会清勾选/备注，提示在输入末尾，不容易注意 |
| 询问清单 | Offer两问可编辑、标记、移除、复制/导出 | 集中收集方便；缺少回到原事务/原条款入口；空状态仍只引导去核对合同，未体现八模块 |
| 保存 | 从离职切回社保，1步勾选和备注仍在；刷新后材料/台账清空，2条询问仍保留 | “本次操作保留”和“浏览器保存”容易混淆；这是最应先补的可靠性体验 |

真实导出副本export-leaving.txt；刷新前后记录retention-check.json；本次测试的2条问题已用界面清理，不修改用户5186预览的材料或清单。

## 优先改进清单（建议，尚未实现）

| 优先级 | 问题及影响 | 建议做法 | 完成判据 |
| --- | --- | --- | --- |
| P1 | 目录、模型、标题、底部导航的选择/进入含义不同；用户需猜操作 | 标题、目录行、底部统一一击进入；把旋转/选择保留给独立观景操作，或对预览明确写“预览” | 从任一标明“进入”的入口，一次动作到同一工作区，返回保留选中 |
| P1 | 刷新丢材料和台账，保存提示不明确 | 提供用户可控的本地草稿保存与清除，清楚标记“已保存到本机/仅本次会话”；落地前至少在输入和导出旁写明刷新边界 | 关闭/刷新后行为与界面承诺一致；个人材料不默默上传 |
| P1 | Offer/个税一次展示过多专业字段 | 先展开少量必填；可选项折叠；每项加“去哪里找/不知道怎么办”，保留未知，不能填假数字 | 不懂术语的新用户可完成最小合法输入，或者明确知道下一步去哪里查 |
| P1 | 官方跳转后缺少具体导航；个人勾选可能被当办结 | 链接写明平台名称、目标业务、站内搜索词和地区选择；保持“个人记录/官方进度”区分 | 新人到平台后无需猜该点哪一类业务；不把勾选说成官方完成 |
| P2 | 字小、辅助字色浅、移动中的三维标题难点 | 工作区增大关键辅助字和对比度；指向目标时稳定标签，保留清楚的文字导航 | 桌面普通缩放下能看清范围、待确认原因和主动作，不依靠精确点三维小字 |
| P2 | 示例如自动生成/只填入两种行为混在一起 | 统一“载入示例”与“载入并体验”的动词，所有结果与导出保留来源标记 | 用户能判断当前是自己的材料还是合成体验，以及是否还需处理 |
| P2 | 补贴覆盖范围、照片预览能力在进入后才详细说明 | 在入口旁简短标注“广州示例”；上传旁明确“照片仅预览，请补文字”并提供粘贴步骤 | 用户在准备材料前就知道工具是否适合自己 |
| P2 | 清单问题失去原事务语境、空清单仍只说合同 | 为每问保留来源事务/引用定位并可返回；空状态写“从任一事务整理问题” | 从问题能回到对应证据或材料，不需全站重新找 |

这些是下一轮产品体验改进，不冒充本轮已经交付。当前业务仍是八项限定范围本地工具，在线AI/OCR/RAG/Agent未接入。整体审美仍待用户评价，未将内部自检当成用户认可。
