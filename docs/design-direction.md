# 视觉方向：理性的未来感

> 历史草案：用户已否定浅色纸张/档案方向。当前以 design-mechanical-v0.1.md、mechanical.css 和 BioCore.tsx 为准，不按本文旧浅色板恢复界面。

本文是设计方向与实现约束，不代表所有界面已完成。主题转译服务于毕业生入职与生活办事，不从游戏设定推导产品业务。

## 业务与主题边界

本项目面向刚毕业、初入职场的人。十四个办事卡点属于长期路线图；当前核心为劳动合同核对、工资条与五险一金解释计算、补贴资格匹配及办理导航。首版以劳动合同核对为主线，工资与补贴为辅助。

“莱茵生命”是队名与 UI 主题参考。取其科研机构、档案管理、精确排版的视觉气质。产品仍使用“合同条款”“本期扣款”“申报条件”“官方依据”等直接业务语言。角色、剧情、游戏任务、虚构研究部门均不进入业务流程。

## 转译原则

1. **清晰的机构感。** 用整齐的列、编号、小型元数据和细分隔线建立秩序，内容以实际任务为中心。
2. **依据可见。** 地区、适用人群、生效时间、申报期和核验日期形成一致的资料栏；官方来源入口紧邻结论。
3. **主次明确。** 先呈现“当前要做什么”和主要结果，再展示解释、公式、依据与补充材料。避免用户先读一屏技术说明。
4. **视觉表达状态。** 缺信息、需要核对和计算完成使用不同文字状态，不让用户从颜色猜含义。
5. **克制的未来感。** 保留科研排版与轻量动态；不复制游戏角色、游戏 Logo、活动大背景或整屏活动菜单。复杂 3D、全屏玻璃阵列和持续粒子不是本项目要求。

## 建议配色

以下是面向可读性的候选色板，**非官方取色**。实现后须以实际字号、背景、禁用态和焦点态检查对比度。

| 用途 | 建议值 | 使用约束 |
|---|---|---|
| 页面背景 | `#F3F5F0` | 大面积安静的灰白底色 |
| 内容表面 | `#FFFFFF` | 用于需要明确边界的表单、原文和结果区域，避免每个短句一张卡片 |
| 主要正文 | `#16221F` | 正文、金额、关键标题；不降低重要数字的对比度 |
| 次级正文 | `#59665E` | 来源元数据和辅助说明，不能用于缩小字号的关键条件 |
| 品牌／主要操作 | `#436951` | 当前任务、主要按钮、小面积强调；不代表法律结论或补贴获批 |
| 轻强调底色 | `#E4EBE0` | 当前分区、选中行或补充信息区域 |
| 分隔线 | `#CFD7CC` | 细线分区，避免用粗边框制造信息层级 |
| 待确认提示 | `#D98645` | 小图标、标记或浅色底提示；不直接用白色小字叠加在橙色上 |
| 错误／需处理 | `#B24B45` | 输入格式错误或无法继续；不能把所有疑问一律渲染成“违法”警报 |

颜色应与文字、图标共同表达状态。合同、工资和补贴不各自使用一套高饱和配色。

## 网格与布局

- 桌面采用稳定的导航和主任务区；主内容可用 12 列网格，页面最大内容宽度建议约 1280 px，列间距约 24 px。
- 合同页面以原文／已确认字段和核对结果并排呈现；宽度不足时按阅读顺序上下排列。
- 工资页面让输入项、个人扣款、计算过程和结果直接对应，金额列对齐。
- 补贴页面先显示地区与个人条件，再显示条件核对和官网办理入口。
- 主要操作每个任务区保留一个高强调按钮。次级操作使用普通文字或轻量按钮。
- 使用 4／8 px 间距基准；容器按需要使用小圆角和细边框。避免大面积阴影、斜切卡片、叠层 HUD 和装饰性网格遮挡正文。
- 手机端优先一列完成当前任务；来源和条款详情可展开，但影响金额或资格的关键条件不能默认藏起。

## 字体与信息层级

- 中文使用清楚的无衬线字体，可采用系统黑体回退；若引入外部字体，先确认加载和授权。没有依据指定“官方同款字体”。
- 正文建议 16 px，必要的元数据不低于 12 px；表单标签和条件文本保持舒适阅读大小。
- 金额、比例、日期、编号使用等宽数字特性；中文正文不改成等宽终端字体。
- 页面标题、当前任务、区块标题、正文和来源元数据形成有限的层级，避免每块内容都使用大标题。
- 英文只用于少量辅助标签或队名展示；中文业务名称优先，用户不需要理解英文才能完成操作。
- 数字必须配单位、时间范围和含义，例如“本期已输入个人扣款”，不能只显示没有定义的金额卡片。

## 状态与可信度

| 状态 | 应表达的意思 | 不应暗示 |
|---|---|---|
| 材料未说明 | 当前材料没有提供该字段或条款 | 事实不存在、公司一定违规 |
| 条件待补充 | 地区、时间、金额或个人条件不足 | 已经通过资格核验 |
| 需要核对 | 存在不一致或需要用户确认的内容 | 已确认违法或存在欺诈 |
| 计算完成 | 在所列输入和规则版本下完成确定性计算 | 工资条必然正确、税务机关已确认 |
| 条件初步匹配 | 已输入条件与已核验的规则相符 | 补贴一定获批或一定到账 |
| 官方依据待核验 | 资料未完成时效与适用范围核验 | 使用主题样式包装成官方认证 |

本地交互原型、示例数据与未来的在线 AI 能力必须清楚区分。对外表现以实际实现为准。

## 图标、边框与动效

- 图标采用统一线宽的文档、计算、日历、定位、外链、提示等普通功能图标，尽量配文字。
- 细分隔线、短编号和角标可以呼应科研档案；不把普通材料称为“机密档案”，不把查看结果称为“解密”。
- 建议过渡时长 150–220 ms，以淡入、颜色变化或很短的位移为主。这是建议时长，不是官方动效测量。
- 尊重减少动态效果设置；自动动画不能影响输入、阅读和键盘焦点。
- 只显示真实操作状态。本地规则校验完成后直接给结果；尚未接入 AI／OCR／RAG 时，不播放“AI 正在分析”“正在检索政策”等假进度。
- 实际异步能力接入后，进度必须来自请求、工具或任务状态；无法确定百分比时使用真实的阶段说明与取消／重试入口。

## 视觉验收

- 宽屏、窄屏、键盘操作均能完成主任务，表格与金额不溢出。
- 主要文字与实际背景达到适当对比度；橙色和绿色的语义不依赖颜色识别。
- 每个重点结果都能找到适用条件、输入依据和来源入口。
- 首屏能看懂当前任务、尚缺信息以及下一步操作。
- 主题只增强可读性与辨识度，不增加虚构流程或额外操作。
