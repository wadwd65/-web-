# v0.31 首页渲染开销优化

2026-11-01。对应用户“主界面偶尔卡一下，在不影响画面的情况下优化帧率”。本轮只减冗余开销，不重做配色、模型或布局。

## 原因与修改

|根因|实际修改|保留的效果|
|---|---|---|
|CSSOM会规范化transform字符串，读回值与原字符串不同，导致相同位置仍每帧写入|独立style-writer缓存上次赋值，仅变化时写DOM；有规范化回归测试|三维文字位置、跟随和可点击子选项|
|八组相同尺寸的几何重复创建|按尺寸与分段共享几何；销毁时去重释放|所有形状、倒角与材质|
|静态节点不断更新局部矩阵；世界矩阵有重复遍历|静态局部矩阵固定，运动节点保留动态；每帧统一一次世界矩阵更新，镜头仍正常更新|拖动、聚焦、展开、粒子迁移、灯光运动|
|15个相同脉冲各自提交绘制|合为一个InstancedMesh，每个实例仍按原路径和时间运动|脉冲数量、尺寸、颜色与轨迹|
|拾取在不可见分支上多做工作并临时分配数组|复用射线结果数组，先排除不可见目标，包围盒提前计算|前景子选项可点，后排只预览；手势判定未放宽|
|仅悬停/聚焦播放器入口就解析GLB并创建隐藏WebGL场景|预取只缓存模块和模型字节，实际打开才解析和建场景；并发去重、失败可重试|准备/进入/退出状态机、唱片抽取、单audio与播放旋转|

没有降低像素比上限1.5、14000环境点与10000形变点、阴影1024分辨率及约10Hz刷新，也没有限制FPS。CSS没有变更。相同物体的资源共享不等于删减物体。

## 对照采样

同一桌面浏览器1280×720、DPR1.5，生产构建、首页静置、未同时运行音乐场景。下面是已保存窗口的代表值，非同一时长的严格硬件基准。CPU值只反映被诊断代码计时的JS/提交段，不包含完整GPU耗时。

|指标|v0.30|v0.31|解释|
|---|---:|---:|---|
|渲染FPS|164|164.5|已接近本机约165Hz上限，不能宣称帧率翻倍|
|帧间隔p95|6.9ms|6.8ms|本机稳态变化很小|
|CPU帧p95|2.1ms|1.4ms|其他优化后窗口约1.1–1.4ms；是减少余量消耗|
|DOM写入/秒|1332|9|同位置不再重复写入；其他窗口约12–18|
|几何资源数|153|25|完全相同几何共享|
|代表帧draw calls|146|139|阴影刷新时会波动，不取最小值做宣传|
|悬停播放器后音乐canvas数|1|0|真正打开后才创建；不是停用音乐|

实例化使一小部分屏外脉冲交给GPU裁剪，因此代表帧三角形12050→12302，不能称面数减少。两次窗口均无最近2秒长任务，不证明低配置机器不会卡顿。

证据位于outputs/v031-perf：baseline-idle.json、after-idle.json、after-hover.json及前后画面。仅在独立QA页操作，未驱动用户已有填写页。

## 验证与范围

- 70项自动测试、TypeScript与生产构建通过；新增4项针对DOM去重、预取不解析、并发与失败恢复的测试。
- 实点前景合同材料可进入原合同工具；后排只预览策略与慢拖/跨区域保护回归测试通过。
- 实际打开三维音乐、抽取档案、播放与旋转、返回原页面；单audio不重建。
- 首页画面、标志、材质、文字和动态保持；这只是内部审查，不替代用户审美验收。
- Three共享包约583KB警告仍在；低配实机、冷启动尖峰、双模式和低帧自动降级仍待做。本轮没有实现画质自动下降，也不把高配采样当成低配验收。

后续步骤与更新评分见[33号改进表](33-score-and-improvement-plan-v031.md)，当前事实以docs/memory为入口。
