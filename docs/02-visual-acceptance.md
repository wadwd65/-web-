# 交付前视觉自检要求

来源：2026-10-28用户明确要求“成果必须自检，不好看直接重做”，并指出实现作为模板可用，但持续没有命中想要的视觉体验。本文件是下一轮必须执行的验收，不是声称已经通过。

## 验收顺序

先看真三维与完整动态，再看美感、功能可辨性与稳定性。构建、规则测试、单帧截图或自评分数都不能代替视觉验收。不同层面的通过要分开记录。

### 真实空间

- 正面、明显侧向和另一观察位置能看出厚度、遮挡与前后关系；不是贴图平面或浅深度图片。
- 光照、阴影、玻璃/金属层次属于同一空间，没有孤立模型加不相干背景。
- 场景具有整体构图，视觉主体不能只是产品名字、抽象摆件或普通后台卡片。

### 转点与场景转换

- 实体A、粒子A、迁移中、粒子B、实体B逐阶段检查；同时观看完整连续过程。
- 点云在轮廓、坐标和比例上对应实体，来自真实网格。
- 从侧面看粒子也有真实体积；不是图像像素网格或凭亮度假造深度。
- 镜头、实体消解、粒子路径、重组成形、UI变化共用可控节奏，不闪白、不乱切。
- 中途快速点击与反向选择连续可控；场景不会被旧加载或旧动画抢回。

### 整体审美与对照

- 将场景全屏、带完整界面、打开功能工作区三种状态放在一起看。
- 与已保存银蓝版的材质、光影和空间层次对照；不能用“技术更复杂”解释更差的画面。
- 重点检查比例、留白、明暗主次、色彩统一、镜头高度及焦点位置；不只堆玻璃和粒子。
- 不为了新鲜恢复已否定的具体造型，不借“高级感”遮掩缺少构图。
- 用独立审视或可用的第二评审检查：画面是否只是换了一个漂亮模板，核心场景与动态是否已经对齐用户参考。
- 审美检查未通过，先内部改构图、模型或节奏，不把明显失败的中间版本作为成品交付。也不能声称个人主观评分代表用户已认可。

### 可用性与桌面质量

- 八模块入口明确，操作不依赖观看完整动画或掌握三维拖动。
- 场景以视觉与任务入口为用途，正文和表单保持稳定、清楚。
- 文字不被高光、粒子或大模型遮挡，尽量用开放排字、细线和选中标记。
- 隐藏工作区不丢当前会话表单；鼠标拖动不误开功能。
- 检查约1280宽桌面与用户当前约834宽桌面窗口；不追加手机工作。
- 减少动态效果与静态退路可用；性能以实测记录，未测就不写帧率保证。

## 每次内部验收记录

保存：不同观察角度、转场关键帧、完整动态观察结论、完整UI、工作区、快速连续选择结果，以及已发现并已修复的问题。未达标项不能用“构建通过”划掉。

交给用户时只说明实际完成的效果、仍有的限制与可查看成果。用户负责评价创意是否命中喜好，不应再替开发者排查基础视觉错误。
