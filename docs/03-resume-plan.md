## 先完成一段完整体验

1. 读取`01-true-3d-research.md`与`02-visual-acceptance.md`，核对四个参考及否定记录。不要直接把旧版本当新模板继续调皮肤。
2. 核验本机真实建模工具、可用连接及当前Three r183接口。Blender/MCP尚未安装或连接的事实要如实说明，不能假称已有建模结果。
3. 独立制作两个有真实深度、厚度和遮挡的小型场景，保留可编辑工程或清楚的程序化几何源。先把整体空间、材质与镜头构图做好，不采用名字雕塑、旧翼片/DNA/阶梯展架等被否定造型。
4. 做完同一段连续过程：**实体A → 表面粒子显现 → 粒子空间迁移及镜头转场 → 按场景B真实几何聚拢 → 实体B恢复**。不要在关键阶段用图片轮换或两个渲染结果淡入淡出来替代。
5. 在独立测试环境完成不同角度、关键帧和连续动态自检。不好看或不连续，先内部重做，不能又把明显失败版交给用户判断。
6. 核心质量通过后，再接入八模块的场景控制器、统一入场与可收起工作区。八项不应同时加载/运行八套转场；按实际性能决定资产预载、缓存与释放策略。

## 近期技术选择

建议主链：Blender → GLB/glTF → Three.js r183/WebGL → MeshSurfaceSampler → Points/ShaderMaterial → 单一时间轴。GSAP用于同步，GPGPU用于确有需要的持续受力。Theatre.js/Spline/PlayCanvas/WebGPU仅为已调研备选，不要一次全部加入。

采样要遍历场景Mesh并统一世界矩阵；非均匀缩放先烘焙，点数按表面积与构图权重分配。A/B保持固定总点数和连续映射。转场中只处理最后一个等待目标，防止异步加载和多条动画互相覆盖。

工具链和技术路线是调研结论；两个场景的具体造型、构图与风格仍未确定，不能把它们写成用户已批准的方案。
