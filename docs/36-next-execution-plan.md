# v0.32之后的执行计划

制定日2026-11-01；依据35号再审、34号实现事实和用户“按上面要求计划后续”请求。本轮仅制定计划并更新项目记忆，不修改应用、不发布新版本。以下v0.33–0.37是拟定里程碑，不能当作已实现功能。

## 交付目标

让第一次签劳动合同的毕业生提交材料、校对关键信息、得到有来源的核对结果，再带走一份可编辑的询问清单。保留八工具及手动路径，合同主线优先做完整；工资作为现有规则核算的回归样例。

保留浅色银蓝、完整三维、简易/完整、前景子选项防误触、单audio和音乐原交互。UI优化收敛到入口主次、文字色阶、聊天操作层级、结果阅读。不重做模型或另开视觉方向。历史可视化的黑白工程终端选项不能覆盖当前浅色要求。

## 实施边界和失败收缩

- 长对话不是无限发送历史：保留用户确认的结构化事实和原话证据、更新/撤回记录与近期上下文，保持服务端容量和成本边界；模型总结不能升级成用户已确认事实。
- 关闭聊天与停止请求要在实现前明确区分。若允许隐藏后继续，必须可见地提示仍在处理并能恢复；停止仍应真的取消，不能悄悄后台续跑。
- 阶段提示只能来自实际服务事件；若暂时只能等待一次响应，明确“等待回复”，不用虚构百分比。没有必要为动画单独引入复杂框架。
- 不假设当前DeepSeek模型支持图片。若当前接口不支持，最多评估一种独立OCR方案，明确新增服务配置和显式材料发送；需额外账号/密钥时说明缺项，不把文本模板或人工粘贴伪装成识图。单图8小时预算内难以稳定，先保留文字校对路径并如实记录图像缺口。
- RAG先少量权威资料，不扩全国补贴/社保库。11/8仍不稳定，缩小资料范围并修检索，不扩技术栈；静态来源链接不能称RAG。
- 八工具不要求同时做成八个复杂Agent。现有工资/合同规则继续共用；未知金额不当0，资格不猜，用户已有材料不自动发送。
- 11/10主线仍不稳定时，优先完成文字材料→依据→清单，并明确图像/检索实际状态。11/14以后只修缺陷、补交付，不用抬高分数掩盖缺口。
- 本机助手与公网开放分开验收。若需要公网AI演示，先补访问/额度隔离并计入缓冲；时间不够则公开前端与手工工具、AI使用受控演示环境，不能把无保护的密钥网关开放给所有人，也不能声称公网AI已完成。

## 每轮审核与回退

1. 从当前保存点开始，只完成本轮目标，保留上轮可运行版本。
2. 核对真实能力、原文/金额证据、失败恢复；涉及逻辑才增加有意义测试，不靠测试数量代替质量。
3. 在独立QA页走完整过程，检查桌面正常/较窄视口的层次、可读性、按钮可见性、动效与状态保留，不操作用户正在填写的页面。
4. 主题偏离或效果倒退，撤回该候选；保留已验证业务，重做有问题的布局/实现，不反复推翻全站。内部审核不能替代用户认可。
5. 源码/构建/参赛快照对应，更新事实、证据和缺口，运行memory:check和memory:stamp；发布只用wadwd65/-web-，不动campus-insight。
