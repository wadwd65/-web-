# 连续动态终端：本轮澄清与下一步验收

日期：2026-10-28。状态：设计约束已澄清，尚未实现本方案，不是新版本交付。

## 用户的重点

用户认为v0.4与v0.11是此前最好的两版；不足是空旷和信息量没有凸显。核心诉求一直是多事务、多工作状态之间连续的动态切换。此前工作把过多时间用于一张首页，更换模型与构图，其他页面缺乏同等完整的动态表达。

以两版为参考不代表直接恢复旧版、不代表所有细节已认可。八模块仍是基础，仅电脑端；业务规则和现有能力边界不扩张。

## 以整段体验为设计单位

| 转换 | 动态表达 | 必须保留的产品信息 |
| --- | --- | --- |
| 入场→总览 | 空间与八个事务位置依次建立，随后稳定 | 模块名称、可体验/待开发、真实会话状态 |
| 总览→选中事务 | 所选资料抽取到前景，其余对象退后，镜头连续跟随 | 所选事务名称、当前材料/状态、明确进入动作 |
| 选中→工作区 | 从所选资料延伸出可阅读与填写的工作表面，沿用同一视觉对象 | 输入要求、当前材料、主要操作；不让大模型挤占正文 |
| 填写→核对结果 | 根据已产生的真实结果展开信息层或金额结构 | 原文、待确认项、计算过程、适用范围；不得演假AI分析 |
| 结果→原文/依据 | 对应内容定位、突出关联，其他信息退弱 | 具体原文位置、依据链接、未知和疑点的区分 |
| 结果→清单/记录 | 已选问题或已生成记录有明确的归集反馈 | 真实条目、导出状态；没有保存的数据不伪装成已留证 |
| 工作区→总览 | 工作表面收回对应资料，镜头回到先前位置 | 保留填写、结果、当前选择与状态摘要 |
| 合同→工资等跨事务 | 旧资料归位，新事务接续抽取；同一控制器管理镜头和界面 | 八项入口始终明确，待开发模块不冒充已有结果 |

第一条完整样段应覆盖：总览→合同→合成材料→实际规则结果→原文定位→返回→工资→计算结果→返回。八模块位置和入口一开始就纳入调度，不以一个首页完成度冒充整个体验。

## 信息量如何进入空间

v0.4提供资料阵列和前后层次，v0.11提供任务与资料的可理解性。主要信息来自实际材料和办理状态，不再让大量重复空页、装饰性英文或无关建筑占据焦点。

例如合同合成示例可呈现真实的277字材料、7个已核对项与3个待确认项，以及试用期、工作地点和违约金三类问题。它们必须明确标合成示例，不能凭空补造用户档案。工资、补贴同样使用现有计算与条件状态。无材料时显示清楚的输入入口与简短能力说明。

## 动态验收

- 同时检查相邻状态如何进入、如何停稳、如何返回，而不只看单帧首页。
- 入场、事务选择、工作区、结果、返回和跨事务都具有同一套材质、排字与运动语言。
- 单一控制器处理连续选择，只保留最后一个待切目标，不乱切、不重复播放入场。
- 操作不依赖看完演出，填写和阅读期间文字保持稳定。减少动态模式覆盖场景及DOM动效。
- 核对/计算已经真实产生结果后才展现结果层；动画不代表模型正在调用、权限验证或后台任务。
- 以真实三维对象和几何转点作为可复用技术，避免为每个动作硬塞完整转点动画。
- 在1280宽与约834宽桌面检查整条操作链，不做手机适配。

完整连续体验通过前，不把首页截图、构建通过或几何效果质量当作产品视觉已经完成。
