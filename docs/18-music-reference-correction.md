## 当前独立实现

1. **五首歌对应五张真实 Three.js 档案**，没有用几十张假曲目填满阵列。程序化金属边、铰接玻璃、实体唱片、索引、曲名、艺人和时长；所有标签与圆形图案由本项目生成。没有复制参考模型、源代码、封面或 CG。
2. **目录 → 悬停预览 → 抽取 → 单曲详情 → 收回**共用同一场景和同一批几何。入场只做一次短的阵列推进，固定世界位置；不自动选歌、不无限重排。
3. 目录行和实体模型均可展开同一曲目。悬停抬升与边缘高亮，轻量视差；详情可拖动看侧面、滚轮缩放。快速换对象先收回旧档案，再抽取最终对象，避免瞬移。
4. 详情与正在播放的对象分开。打开档案不切音源；“播放所选曲目”才应用。底部仍显示真实播放曲目、前后曲、播放/暂停、音量、静音、循环、进度定位。
5. 外部“播放器”进入阵列；“切歌”切下一首并自动抽取其详情。原本暂停则保持暂停。内部翻档案不播放，底部上/下一首沿用已有播放逻辑。
6. Esc 在详情先收回阵列，再按一次返回原事务；显式返回事务按钮直接返回。键盘目录 ↑↓ 选择、Enter 展开；详情空格播放控制，左右键定位实际播放曲目的前后 5 秒。原生滑块与按钮按键仍各自有效。
7. 原八事务、材料和现有音频引擎保持。音乐仅为辅助页，不能将初程改成与办事工具脱节的音乐服务。

## 性能与边界

Three.js 异步加载；音乐显示时原事务三维暂停；离开音乐释放音乐场景的几何、贴图、材质、事件和渲染器。DPR 上限 1.35，重复细部实例绘制，纹理只生成一次，阴影只在几何移动时限频更新。后台暂停，减少动态关闭入场波动、视差、尘埃位移和唱片转动。阻尼按真实帧间隔计算，避免被节流时固定 40ms 步长拉成长时间慢动作。三维失败仍可选歌/播放，并有重试入口。

v0.20 的离线音频采样数据/工具和音频分析链保留为历史与可复用能力，但本版不再摆两块声波图。五首本地音频与来源说明延续，不新增下载、不声称商业再分发许可。

视觉采用银蓝、冷白与少量曲目色，既保留 v0.4 的空间纵深，也保留 v0.11 模型承载真实文字的优点。内部审核不能替代用户审美认可。
