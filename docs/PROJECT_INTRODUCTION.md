## 项目详情与使用

刚入职时，常见的难处不是没有搜索框，而是不知道该看哪项、还缺什么、下一句该怎么问。初程把毕业生会遇到的八件事放在一起：Offer对比、劳动合同核对、工资明细、个税指引、社保医保、租房核对、城市政策和离职转接。

用户可以直接说问题，也可以不使用AI，进入工具自行核对。已确认的信息用于计算，未知留空；需要问HR或房东的事项加入清单，修改后导出。登录可选，材料不会因打开页面自动发送。三维终端提供入口、预览与转场，音乐是辅助体验。

运行方式：全部解压Windows即用ZIP，双击“开始使用.cmd”，保持服务窗口开启；不需管理员权限、npm安装或另装Node。源码运行见README，需要Node>=24.21.0、npm ci、npm run build、npm start。不能直接双击dist/index.html代替服务端。

AI需要网络和维护者配置的比赛接口；也可在右上角“API设置”使用自己的官方DeepSeek。自备接口不占本站每日提问/识图额度，费用由自己的提供者账号承担，仍有并发与短时频率保护。提交包不包含密钥。

## 亮点

- 先说情况，再补真正必要的信息。问候、第一次使用、不想填表可自然交流；计算才核对金额，不让每个问题都变成表格。
- 把“解释”与“算数”接起来。真实模型作有限规划与文字解释，工资由可核验的本地函数按分计算；用户确认后才写入工具。
- 保留来源和边界。合同查有限官方摘录，城市目录按地区、人群和核验日期展示，未知不代填、不承诺资格。
- 结果能带走。核实点保留原文线索，可改问题、记录答复并导出；不是停在一段聊天文字。
- 动态三维与简易模式共用业务。完整模式提供前景子项、抽取、切换及辅助音乐；简易卸载重场景，保留填写、对话和音频。

## AI技术实际落地

同源Node网关真实调用DeepSeek。流程为用户表述→有限事项规划→白名单工具（计算、合同资料、城市目录、清单等）→解释与可核对结果→用户显式应用。它是受限多步工作流，不宣称自主通用Agent或任意工具控制。

RAG是小范围官方劳动合同摘录，带版本、核验日、范围和原文来源；四城目录共12条三类资料，区级、院校和申请期限制单独说明。其他城市仅有固定官方目录的求职住宿发现，未实现全国现金政策搜索。

PNG/JPEG可明确发送模型识别，人工对照并确认文字后用于核对。数字PDF在浏览器本地提取，8MB/30页，校对后主动带入；扫描PDF不提供整份OCR，不能把文件预览当成已读全文。

模型密钥在服务端。用户自备Key只临时保存在服务端内存约一小时，不进入浏览器长期存储、账号、日志或作品包；账号与用量数据库在工程外。规则结果、模型回复和安全兜底分别标识。

本轮有24题冻结回归及14题本轮事先冻结验收、真实模型调用、9对生成层资料对照。具体结果、失败记录和限制见EVALUATION.md；不是外部准确率评测。

## 关键技术

React、TypeScript、Vite构建桌面Web；Three.js提供真实三维场景与材质；Node HTTP/SQLite提供同源接口、可选账号与额度隔离；PDF.js在本机提取数字PDF；单audio贯穿路由，资源按需加载。工资证据核验区分确认值、未知、更正与撤回，工具动作需要用户点击。
