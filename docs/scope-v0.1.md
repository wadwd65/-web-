# v0.1 范围：毕业生入职与办事助手

本文规定当前原型的范围和真实性边界，不代表所有条目已实现。实际完成情况以应用行为与验证记录为准。

## 已确定的方向

项目面向刚毕业、初入职场的人，帮助理解入职与生活办事事项。参赛方向为第九届传智杯 AI Web，目标争取国三，不承诺奖项或虚构获奖概率。

十四个卡点是后续路线图。v0.1 围绕一条主要流程展开：**确认劳动合同关键信息，看到需要补充或核对的事项，再进入工资拆分或补贴办理辅助。**

“莱茵生命”仅作为队名和 UI 视觉参考，具体转译见 [视觉方向](design-direction.md)。不围绕已放弃的旧项目继续立项，也不使用旧参赛包充当本项目的验证样本。

## 当前交付的性质

**这次只做本地规则交互原型。AI、OCR、RAG 和在线政策检索尚属后续接入范围。**

原型用于验证用户能否理解页面、填写必要信息、看懂计算与核对结果，并找到下一步。它不是已经完成的 AI 参赛成品。

- 示例材料须清楚标为虚构或演示，不能伪装成真实个人合同、真实工资条或已获批案例。
- 如果展示文件选择入口而尚未解析正文，应写明“已选择文件，尚未读取正文”，不能假装识别出条款或数字。
- 本地规则执行就按本地规则描述，不出现假 AI 对话、假模型结论、假工具调用日志或假分析进度。
- 后续接入真实能力后，再分别验证识别、检索、生成、规则工具及失败处理，更新能力说明。

## 主线：劳动合同核对

### 用户任务

用户通过示例或手工确认关键信息，理解合同中哪些事项已经明确、哪些没有写清、哪些需要进一步核对。

### 当前原型范围

1. 选择任务并了解当前材料输入方式。
2. 填写或确认与劳动关系相关的关键字段，例如合同期限、岗位与工作地点、工资组成、试用安排等。具体字段以界面和已核验规则为准。
3. 本地规则检查必填信息、格式、数值关系和相互矛盾的输入。
4. 将结果分为“材料未说明”“条件待补充”“需要核对”等可解释状态，标出相应字段。
5. 让用户修改信息，并立即看到受影响的结果变化。
6. 提供下一步需要向用人单位确认的问题，以及可追溯的官方来源入口；未核验来源必须明确标记。

原型不凭模板完整度认定合同合法，也不把材料缺失直接定性为违法。涉及具体权利义务的提示，须绑定适用的官方依据后再对真实材料使用。

## 辅助一：工资条与五险一金

### 用户任务

理解应发、本人扣款、单位缴费和实际到账的区别，知道计算使用了哪些输入和规则。

### 当前原型范围

- 支持输入已知工资项目和扣款，逐项解释其位置与用途。
- 对已知金额执行可测试的加减计算，并把公式和输入展示出来。
- 个人承担部分与单位承担部分分开显示，不能把单位缴费直接算作个人工资扣款。
- 计算税费或社保、公积金缴费前，必须明确地区、所属期间、缴费基数、比例及规则版本。
- 尚未绑定已核验税费规则时，只计算用户已知金额的拆分，不默认填入某地比例，不自由估算个人所得税。
- 修改一个输入后重算结果；缺少参数时显示待补充，不能偷偷使用隐藏默认值。

本地计算说明输入与规则下的结果，不保证工资条无误、退税成功或实际到手金额与预测一致。

## 辅助二：补贴条件与办理导航

### 用户任务

知道应核对哪些资格条件、缺什么材料，以及到哪个官方入口查看或办理。

### 当前原型范围

- 优先确认地区、适用人群、毕业／就业等相关时间与已知个人条件。
- 按条件逐项展示已满足、未满足和未知；未知不能自动当成满足或不满足。
- 每项具体政策必须展示发布机构、官方链接、适用地区、人群、生效时间、申报期及核验日期。
- 未接入有效政策数据时，只演示条件核对和导航的交互，不宣称已经匹配真实补贴资格。
- 办理导航应链接到可核对的官方页面，并列明仍需要用户确认的条件。
- 不自动提交申请，不保证审核通过或金额到账。

## 规则和资料的数据边界

凡涉及劳动、税务、社保、公积金或补贴的实际结论，至少需要以下信息：

| 字段 | 用途 |
|---|---|
| 官方发布机构与原文链接 | 追溯依据 |
| 规则或政策名称／版本 | 区分不同依据 |
| 地区与适用人群 | 避免套用其他地区或对象的规则 |
| 生效时间、失效信息、申报期 | 判断时间适用性；未明确时保留未知 |
| 核验日期 | 告知最近一次核对时间 |
| 计算参数与单位 | 避免金额、比例、基数和期间混淆 |
| 条件状态与缺失信息 | 区分未知、疑点和已经证实的输入事实 |

公式与规则工具负责金额和条件计算；模型后续只承担材料理解、解释、检索协助和任务编排，不自由编造计算参数或资格结果。

## 后续 AI 能力接入

后续能力按实际任务逐步接入，不能以页面按钮存在代替能力完成：

1. **OCR／多模态读取：** 读取用户主动提交的材料，保留原文定位；低置信字段交由用户确认，识别结果不能直接成为事实。
2. **RAG：** 检索适用地区和时间范围的官方材料，返回具体片段与来源；检索不到时明确说明。
3. **大模型解释：** 围绕已确认字段、工具计算结果和检索证据作通俗解释，区分资料未说明与已经证实。
4. **工作流／工具调用：** 根据缺失参数补问，调用可测试的计算和条件核对工具，再解释结果；显示真实执行状态。
5. **失败处理：** 对模型超时、识别失败、来源失效、条件冲突分别提供纠正或重试路径，不降级成看似成功的假结论。

每项能力需使用本项目自己的虚构边界样例与获得授权的真实样例检验，不沿用已放弃项目的资料。

## v0.1 不扩张的范围

- 不一次覆盖全部十四个卡点或全国所有地区。
- 不做复杂 3D、角色扮演、剧情调查、虚构机构业务或游戏化办事。
- 不提供自动签约、自动申报、代缴、代办付款等外部执行。
- 不以“法律风险分数”或“获批概率”代替可追溯的逐项说明。
- 不把本地演示数据、手工输入或规则响应称为已经接入的 AI 能力。

## 当前原型验收

- 首屏能理解主任务；合同核对、工资辅助和补贴导航的关系明确。
- 不填写必要信息时，页面能指出缺什么；修改信息后状态一致更新。
- 数字输入有单位与范围校验；金额计算有独立、可复查的规则测试。
- 缺失、无效、零值、边界值及相互矛盾的输入有明确处理。
- 来源、适用地区、时间和未核验状态可见。
- 示例、已实现本地能力和待接入 AI 能力容易区分，无假 AI 进度。
- 键盘与手机窄屏可完成主要流程，结果与公式不溢出。
- 验证记录如实说明测试范围；本地原型通过不等于线上服务、真实 AI 或法律政策效果通过验收。
